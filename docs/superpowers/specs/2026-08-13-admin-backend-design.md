# PKU M.LEAGUE 比赛后台系统 · 设计文档

**日期：** 2026-08-13
**状态：** 待评审

## Goal

为 PKUML 官网新增一套带登录与角色的后台系统：队长为队伍未来赛程选派出场选手，裁判逐小局录入对局数据并自动生成赛果，管理员管理账号、队伍名单、赛程、公告与对局信息。所有动态数据进入数据库，选手档案等静态内容保留在 JSON。

## 总体架构（混合式）

- **静态站不变**：Astro 继续构建，部署在 GitHub Pages（`/PKUMLonline/`）。
- **动态数据走 Supabase**：托管 Postgres + 账号认证（Auth）+ 行级权限（RLS）+ REST API。GitHub Pages 不动。
- **数据获取方式**：
  - 静态内容（选手档案、往届历史、规则、队伍介绍、队伍颜色）→ 直接导入 JSON，构建时烙进页面。
  - 动态内容（公告、未来赛程+出场、对局赛果）→ **客户端拉取**：页面加载后浏览器 fetch Supabase 渲染，刷新即最新。
  - 积分榜 → 浏览器拉已完赛对局后，**复用现有 `standings.ts` 计算逻辑**在浏览器现算。
- **技术选型**：管理界面用原生 JS + fetch（不引入前端框架）；折线图用 **Chart.js**；积分榜浏览器复用现有代码。

## 角色与权限（RLS）

| 能力 | admin | referee | captain | 公开访客 |
|---|---|---|---|---|
| 读公开数据（公告/赛程/赛果/队伍） | ✓ | ✓ | ✓ | ✓ |
| 账号管理 | ✓ | | | |
| 队伍名单管理 | ✓ | | | |
| 赛程管理（创建/改/删半庄） | ✓ | | | |
| 公告增删改 | ✓ | | | |
| 录入/修改**未完结**半庄 | ✓ | ✓ | | |
| 修改**已完结**半庄（赛果） | ✓ | | | |
| 填自己队伍的出场选手 | ✓（代填） | | ✓（仅本队） | |

- 队长 RLS 校验：`seats.player` 只能写 `team = 当前用户 team` 的座位。
- 裁判 RLS 校验：只能写 `status='upcoming'` 的半庄及其 rounds；已提交成赛果（`finished`）的半庄裁判不可改，仅管理员可改。
- 账号仅管理员创建（Supabase 后台建号 + 设初始密码）。
- 写入一律走登录态；公开读走匿名 key（只读）。

## 对局录入流程（裁判/管理员）

1. 选择一个 `upcoming` 且有 4 名出场选手的半庄进入录入页。
2. 系统自动从第 1 小局（东一局 0本场，亲家=东起）开始。
3. 每小局裁判录：结果（荣和：谁荣和谁 + 点数；自摸：谁自摸 + 点数；荒牌流局：四家听牌）+ 四家是否立直。
4. 点数通过**可点击点数表**选择（番×符），不手输数字。
5. 录完点**下一局**：系统按规则自动算好下一局的局名/本场/亲家，进入下一局录入。
6. 可**倒推**回去改之前的局；改动后系统自动重算受影响小局的局名/本场/供托/累计点数。
7. **南四锁定**：南四局结果为「亲家听牌流局」或「亲家和牌」时才能继续「下一局」；否则只能「提交」。
8. **提交**：系统校验所有局点数平衡 → 计算各家最终分与排名 → 写回该半庄 seats → `status=finished` → 赛果即生成。

**权限锁定**：半庄提交成赛果后裁判不可再修改；管理员仍可修改（改动触发全量重算并更新赛果）。

### 局名 / 本场 / 亲家自动规则

上一局结果 → 本局：
| 上一局结果 | 局名 | 本场 |
|---|---|---|
| 亲家和牌 | 不变（连庄） | +1 |
| 亲家听牌·荒牌流局 | 不变（连庄） | +1 |
| 亲家未听牌·荒牌流局 | 推进 | +1 |
| 子家和牌 | 推进 | 归0 |

亲家 = 局名对应初始座位：东1/南1=东起，东2/南2=南起，东3/南3=西起，东4/南4=北起。

规则无途中流局（九种九牌/四家立直/四杠散了等不存在），荒牌流局是唯一流局类型。

## 对局计算规则

### 中间量
| 量 | 定义 |
|---|---|
| **本场费** | 本场数 × 300 |
| **供托** | 中心累计立直棒数 × 1000（立直棒跨局保留：荒牌流局保留、和了清零） |
| **场供** | 本场费 + 供托 |

### 点数增减（每小局）
| 情况 | 增减 |
|---|---|
| 立直宣告 | 立直者 −1000，入供托池 |
| 荣和 | 赢家 +基础点+本场费；放铳者 −基础点−本场费；赢家再收供托池全部，池清零 |
| 自摸 | 赢家 +基础点总额（按亲子拆分：子付 base、亲付 base×2，向上取整到百）；本场费赢家 +300×本场、三家各 −100×本场；赢家再收供托池，池清零 |
| 荒牌流局 | 罚符（见下）；本场 +1；供托池保留 |

### 荒牌流局罚符（总额固定 3000，与亲家/子家无关）
| 听牌人数 | 听牌家 | 未听牌家 |
|---|---|---|
| 0 或 4 | 无 | 无 |
| 1 | +3000 | 各 −1000 |
| 2 | 各 +1500 | 各 −1500 |
| 3 | 各 +1000 | −3000 |

等价：罚符总额固定 3000，未听牌家各付 3000÷未听人数，听牌家各收 3000÷听牌人数。

### 校验不变量
每小局：四家增减和 + 供托池变化 = 0。不等则拒绝保存并提示。

## 可点击点数表

- 静态数据文件存标准日麻点数表：横轴符数（20/25/30/…/110），纵轴番数（1番~3番，4番满贯并入高番档）。
- 四种视图：子家/亲家 × 荣和/自摸。荣和格子一个数（如子家满贯 8000）；自摸格子为拆分「子付/亲付」（如子家满贯自摸 2000-4000）。
- 满贯及以上档位：满贯 4番 / 跳满 6-7番 / 倍满 8-10番 / 三倍满 11-12番 / 役满。
- 裁判录入时：先定结果类型（荣和/自摸），系统按赢家是否为亲家自动切到对应视图；点格子 = 选中该（番,符）的基础点数。
- 数值校验：与现有日麻标准表一致（20 符=门清自摸/平和，25 符=七对子）。

## 对局详情页

标题：时间 + 半庄信息（如「2026-09-01 14:00 第1半庄」）。

**总表（8行 × 5列，放在上面）**
| | 东起 | 南起 | 西起 | 北起 |
|---|---|---|---|---|
| 队伍 | 队伍A | 队伍B | 队伍C | 队伍D |
| 选手 | 选手名 | … | … | … |
| 立直 | n | n | n | n |
| 荣和 | n | n | n | n |
| 自摸 | n | n | n | n |
| 放铳 | n | n | n | n |
| 积分 | 24000 pts | … | … | … |

队伍单元格底色 = 队伍颜色。

**对局阶段表（9列，每行一个小局，放在总表下方）**
| 局名 | 本场 | {东选手} | {南选手} | {西选手} | {北选手} | 对局结果 | 打点 | 供托 |

每行各选手列 = 该小局结束时该选手的累计点数；对局结果 = 谁荣和谁 / 谁自摸 / 荒牌流局谁听牌；打点 = 和牌基础点数（流局为空）；供托 = 该局供托值。

**折线图（保留）**：Chart.js；x 轴 = 局序（局名），y 轴 = 累计点数；4 条线按各选手所在队伍颜色；悬浮提示。

## 队长选人

- 队长登录后看到**自己队伍**的 upcoming 半庄列表。
- 每个半庄里自己队伍的座位（该座位队伍=自己的队）可从本队 roster 选 1 名选手。
- 半庄进入 finished 后不可再改。
- 4 个座位选手都填齐，该半庄才可被裁判录入。

## 公告

- 公告页面从 DB 拉取（带静态 JSON 回退兜底）。
- admin 在 `/admin/announcements` 增删改。

## 积分榜

- 浏览器从 DB 拉已完赛半庄 → 复用 `standings.ts` 的 `computeTeamBoard` / `computePlayerBoard` 现算队伍榜/个人榜。
- 常规赛从空表开始；半决赛、决赛未开赛时对应榜空缺。

## 数据交接

- 演示数据（队伍榜、个人榜、对局数据、赛程安排）在新赛季上线时清除。
- 《选手档案》（`players_history.json` / `archive.json`）、往届历史、静态内容保留在 JSON。
- 新赛季队伍名单、赛程、对局全部由管理员在系统录入。

## 实施阶段

1. **Phase 1 · 基础设施**：Supabase 项目 + 建表 + Auth + RLS；管理界面骨架（登录/仪表盘）；公告 CRUD。
2. **Phase 2 · 队伍与赛程**：队伍名单管理；赛程管理；队长选人；赛程页显示出场。
3. **Phase 3 · 对局录入**：可点击点数表；录入交互（下一局/倒推/南四锁定/提交）；自动规则与计算；完结→赛果；对局详情页（总表+阶段表+折线图）。
4. **Phase 4 · 打通上线**：积分榜客户端计算；赛果/公告客户端拉取；演示数据交接；新赛季空表初始化；部署。

## 边界情况

- 荒牌流局需录入四家听牌，既用于连庄判定也用于罚符。
- 半庄进行到南四中途手动结束（如比赛中止）：允许在未录满全部小局时提交，系统按已录小局结算。
- 点数表无命中（如裁判选不出对应番符）：允许手动输入基础点数。
- 倒推修改早期小局时，后续局名/本场/供托/累计点数全部重算，需做一致性校验。
- 管理员修改已完结半庄：允许改（含改 rounds、补录、改出场），保存后全量重算并刷新赛果；裁判无权进入此流程。
