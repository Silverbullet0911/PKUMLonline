# PKU M.LEAGUE 官方网站设计文档

日期：2026-08-12
状态：已定稿
参考对象：https://m-league.jp/

## 1. 项目背景与定位

PKU M.LEAGUE（简称 PKUML）是北京大学校内立直麻将爱好者举办的线下立直麻将团体赛。本章程参见 `PKUML章程.txt`。

本网站作为 PKUML 的官方网站，面向**参赛选手内部使用**，用于展示赛程、结果、积分排名、队伍与选手资料、规则章程，并沉淀历届赛季数据。

### 定位边界
- 网站是**数据沉淀 + 排名可视化 + 规则查询**的载体
- 不作为赛事通知的主渠道（章程第10条指定沟通渠道仍为官方送达依据），避免双轨冲突
- 不承担直播、票务、商城、会员等功能

## 2. 必要性分析

1. **信息集中化**：赛程、出场登记、判罚、扣分目前散落在群聊中，网站将信息沉淀为结构化、可回溯的数据。
2. **积分可视化**：章程计分体系复杂（积分折半持越、迟到扣分、未登记扣分等），纯手算易错，网站集中展示排名与扣分明细。
3. **队伍结构承载**：队内指名顺位（第8条）、外援限制（第9条）需要直观展示。
4. **仪式感与名片**：内部赛事也有正式形象，可用于拉新。

## 3. 可行性分析

- **托管成本**：零成本。GitHub Pages / Vercel / Netlify 免费托管静态站。
- **技术门槛**：低。静态站点生成器 + JSON 数据，无需后端。
- **手动录入**：可行。每场录入 4 名选手、顺位、得分、牌谱链接，约几十秒/场。
- **最大风险**：维护持续性。缓解：数据文件格式极简、录入 SOP 文档化。

## 4. 技术方案（方案A）

- 静态站点生成器（Astro 或同类）+ 数据 JSON 文件 + 免费托管
- 数据更新流程：赛事组维护对局结果 → 构建时自动汇总生成队伍榜/个人榜 → 页面渲染
- 往届三届数据一次性录入，之后基本只更新当前赛季

### 升级预留
数据全部按固定 schema 存放于 JSON，页面只做"读数据 → 渲染"。未来接可视化后台时，后台只需向同一 schema 写数据、站点重新构建，前端代码不需大改。因此 JSON 字段命名与结构现在就固定。

## 5. 页面结构

```
PKUML 官网
├── 首页
│   ├─ 赛事简介（一句话）
│   ├─ 当前赛季队伍排名榜（简版）
│   ├─ 最近赛程/结果
│   └─ 最新公告
├── 赛程与结果
│   └─ 各阶段赛程 + 每场对局结果（4人 + 顺位 + 得分 + 牌谱外链）
├── 积分排名（当前赛季核心页）
│   └─ 页签切换：常规赛 | 半决赛 | 决赛
│       └─ 每个页签内：队伍榜 + 个人榜（两张表）
├── 队伍与选手
│   ├─ 当前赛季各队伍（按队分组，列出队员）
│   └─ 往届选手（分类区）
├── 规则与章程
│   ├─ 章程全文（结构化、按条索引）
│   └─ 赛季公告归档
└── 赛季档案
    └─ 历届赛季数据（回填往届三届数据）
```

## 6. 表格规格

### 6.1 队伍榜（三阶段表头不同）

**常规赛**
| 顺位 | 队伍 | 积分 | 素点 | 差 | 晋级线差 | 比赛数 | 1位 | 2位 | 3位 | 4位 |

**半决赛**
| 顺位 | 队伍 | 积分 | 半决赛积分 | 持越 | 半决赛素点 | 差 | 晋级线差 | 比赛数 | 1位 | 2位 | 3位 | 4位 |

**决赛**
| 顺位 | 队伍 | 积分 | 决赛积分 | 持越 | 决赛素点 | 差 | 一位差 | 比赛数 | 1位 | 2位 | 3位 | 4位 |

字段逻辑：
- 队伍列的单元格背景色 = 队伍代表色（见 `data/teams.json`）
- `积分` = `持越` + 本阶段积分（半决赛/决赛的累计总分）；常规赛无持越，`积分` 即常规赛积分
- `差`、`晋级线差`/`一位差` 均基于 `积分` 列计算
- 常规赛晋级线 = 第6名（前6进半决赛）；半决赛晋级线 = 第4名（前4进决赛）；决赛改为 `一位差`（与第1名的分差）
- `差`：与上一名的分差，始终为正，第1名显示 `-`
- `比赛数`：`3/24` 格式（共24场已完3场，总场数按阶段配置）
- `1位`/`2位`/`3位`/`4位`：该阶段获得对应位次次数

### 6.2 个人榜（三阶段表头一致）

| 顺位 | 所属 | 选手名 | 积分 | 素点 | 判罚 | 比赛数 | 平均顺位 | 1位 | 2位 | 3位 | 4位 | 一位率 | 连对率 | 避四率 | 最高分 |

- `判罚`：无则留空
- 一位率/连对率/避四率为百分比
- **三阶段一致的理由**：章程第0条"分数折半持越"针对队伍分数，是队伍级概念；个人成绩按阶段独立统计，个人榜不引入持越列

### 6.3 时间标注

每阶段两张表共用一个时间标注，位于表格外右下角：
- 赛季进行中：`xx月xx日终了时点`
- 赛季结束：`全日程终了`

### 6.4 选手历史成绩表（每选手一张）

| 年份 | 隶属队伍 | 常规赛积分 | 半决赛积分 | 决赛积分 | 常规赛最高分 | 常规赛避四率 | 队伍名次 |

- **未参加某年** → 该年整行不显示
- **参加了但某项无**（如没进半决赛/决赛）→ 该项用 `-` 表示

### 6.5 荣誉展示

- 选手名旁以**纯文字**展示：**个人奖项**（如"25-26赛季MVP"）或 **队伍夺冠**（如"23-24赛季冠军"），个人赏与队伍赏分开
- 位置在成绩表格之前，紧邻姓名
- 选手无照片/图片形象，纯文字展示（不做徽章样式）

## 7. 数据模型（schema 定稿）

```
队伍 team     — 名称、代表色、队长、队员、外援标识（无队徽、无队伍介绍）
选手 player   — 姓名、资格类型（普通/外援）、所属队、队内指名顺位、荣誉列表
往届成绩 record — 选手、年份、隶属队伍、常规赛积分、半决赛积分、决赛积分、
                常规赛最高分、常规赛避四率、队伍名次（用 - 表示无）
赛季 season   — 年份、阶段配置（晋级线名次、总比赛数、阶段名称）
对局 game     — 赛季、阶段、日期、4名选手及顺位得分、牌谱链接、
               video_url（预留，bilibili，当前不展示）
榜单数据      — 队伍榜 / 个人榜每阶段各一份（含时间戳）
公告 news     — 日期、标题、分类、正文
```

## 8. 非目标（本阶段不做）

- 直播/视频功能（数据模型已预留 `video_url` 字段，bilibili 录像链接未来可展示）
- 队伍介绍、队徽
- 选手照片
- 用户登录/个人中心
- 票务、商城
- 可视化后台（预留升级空间，不做实现）

## 9. 未来升级路径

1. 先在现有 JSON 上挂免费后台（如 Decap CMS / 自建简单管理页），前端结构不变
2. 增加 bilibili 录像链接展示
3. 视需求增加站内搜索、判罚公示区
